# PortKill 桌面端工具产品需求文档 (PRD)

## 1. 产品简介

PortKill 是一款专为开发者设计的跨平台桌面端轻量级工具。其核心目的是帮助开发者快速查看系统端口的占用情况，并提供一键清理占用进程的功能，解决日常开发中常见的“端口被占用（EADDRINUSE）”痛点。

## 2. 目标用户与使用场景

- **目标用户**：软件开发者、运维人员。
- **使用场景**：
  - 本地启动 Web 服务（如 `npm run dev`）时提示端口（如 3000, 8080）被占用。
  - 数据库服务（如 MySQL 3306, Redis 6379）端口发生冲突。
  - 需要快速查杀后台残留的僵尸进程。

## 3. 技术选型

- **框架**：Electron
- **前端技术栈**：HTML/CSS/JS (或搭配 React/Vue，根据开发阶段确定)
- **操作系统支持**：macOS, Windows, Linux

## 4. 核心功能需求

### 4.1 端口监控与扫描机制

- **扫描策略（开发者常用端口）**：
  - **背景说明**：计算机共有 65535 个端口，其中 1-1023 为系统保留端口（System Ports），非系统级开发通常不需要去干预这些端口。盲目扫描或关闭保留端口容易导致系统不稳定。
  - **预设端口监听**：软件默认监控一套“常用开发端口白名单”，保证软件启动速度且直击痛点。
    - _前端/Node.js常用_：3000, 4200, 5000, 5173, 8000, 8080
    - _后端/数据库常用_：3306 (MySQL), 5432 (PostgreSQL), 6379 (Redis), 27017 (MongoDB), 8081
  - **自定义搜索与动态拓展**：提供一个搜索输入框，用户可以随时输入任意端口号（如 `9090`）。应用在查询该端口状态后，会自动将其**持久化加入到本地的监听白名单列表中**。这意味着软件会“越用越聪明”，自动适应不同开发者的使用习惯。
- **信息展示列**：
  - **端口号** (Port)
  - **进程名称** (Process Name, 例如 `node`, `java`, `mysqld`)
  - **进程 ID** (PID)
  - **操作区** (结束进程按钮)

### 4.2 进程控制 (杀进程)

- **双重结束策略**：
  - **主操作 (优雅结束)**：点击默认的“结束”按钮，向目标进程发送 `SIGTERM` (Windows 下发送对应的关闭信号)，允许进程清理资源、保存数据并正常退出。
  - **次级操作 (强制结束)**：在主按钮旁边提供一个下拉箭头或右键菜单选项为“强制结束”，向目标进程发送 `SIGKILL` (Windows 下为 `taskkill /F`) 强制无条件终止进程。
- **权限管理提示**：如果由于权限不足（试图结束属于系统 root 用户的进程）导致结束失败，UI 需弹出明确的错误提示（例如：“权限不足，请尝试以管理员身份运行软件”）。

### 4.3 数据状态刷新机制

- **自动刷新**：应用处于前台时，默认每 3~5 秒在后台静默获取一次端口状态，实时更新 UI 列表，防止展示过期信息。
- **手动刷新**：界面顶部提供一个显眼的“刷新”按钮，方便用户随时强制获取最新状态。

### 4.4 系统托盘 (常驻后台)

- 点击主窗口的“关闭”按钮时，应用默认隐藏并最小化到系统托盘（System Tray / 菜单栏），而非完全退出进程。
- 托盘菜单包含功能：
  - 显示主窗口 (Show PortKill)
  - 退出应用 (Quit)

## 5. UI/UX 设计方向建议

- **极简极客风**：采用开发者偏爱的现代设计，支持且默认使用深色模式 (Dark Mode)。界面要克制，无冗余动画，重点突出数据。
- **界面布局框架**：
  - **顶部工具栏**：包含刷新按钮、快速搜索框（输入端口号自动过滤）、系统设置入口。
  - **核心数据表格**：清晰的四列设计（端口、进程名、PID、操作）。占用端口的数据行醒目显示，闲置端口可置灰或隐藏。
  - **交互反馈**：点击“结束进程”时，提供轻量级的 Loading 状态，成功后该行消失或提示“已释放”。
